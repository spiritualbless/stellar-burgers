## О проекте

**Stellar Burgers** — SPA-приложение, в котором пользователь может:

- собрать бургер из булок, соусов и начинок с помощью drag-n-drop конструктора;
- посмотреть детальную информацию по каждому ингредиенту;
- оформить заказ и увидеть его номер в реальном времени;
- просматривать общую ленту заказов (Feed) с live-статусами через WebSocket;
- зарегистрироваться, войти, восстановить пароль;
- смотреть и редактировать профиль, а также историю собственных заказов.

## Архитектура

Проект построен по слоистой (feature-oriented) архитектуре, характерной для React + Redux Toolkit приложений:

```
┌─────────────────────────────────────────────────────────────┐
│                          pages/                              │
│   Страницы-контейнеры: собирают компоненты + данные из store │
└───────────────────────────┬───────────────────────────────────┘
                             │
┌───────────────────────────▼───────────────────────────────────┐
│                        components/                            │
│  Умные (stateful) компоненты: читают/пишут store, содержат     │
│  бизнес-логику (constructor, header, modal-routes, ...)        │
└───────────────────────────┬───────────────────────────────────┘
                             │
┌───────────────────────────▼───────────────────────────────────┐
│                      components/ui/                            │
│   Презентационные ("глупые") компоненты — только props,        │
│   без обращений к store                                        │
└─────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────┐
│                          services/                             │
│  Redux store: slices (createSlice + createAsyncThunk),         │
│  rootReducer, типизированные селекторы и хуки                  │
└───────────────────────────┬───────────────────────────────────┘
                             │
┌───────────────────────────▼───────────────────────────────────┐
│                           utils/                                │
│   burger-api.ts — REST-клиент к Norma API, cookie.ts —          │
│   работа с токенами, types.ts — общие доменные типы             │
└─────────────────────────────────────────────────────────────┘
```

Ключевые архитектурные решения:

- **Разделение "умный / глупый" компонент.** Каждый бизнес-компонент в `components/*` имеет презентационную пару в `components/ui/*` — вся вёрстка и стили изолированы от логики, что упрощает переиспользование и покрытие Storybook/тестами.
- **Redux Toolkit slices** — каждая доменная область (ингредиенты, конструктор, заказ, лента, заказы пользователя, авторизация) — отдельный slice со своим состоянием, редьюсерами и асинхронными thunk'ами.
- **Модальные роуты поверх фона.** Для деталей ингредиента и заказа используется паттерн `location.state.background`: URL меняется, модалка открывается поверх текущей страницы, при обновлении страницы контент открывается на весь экран напрямую по URL.
- **Protected routes.** Компонент `ProtectedRoute` защищает приватные страницы (`/profile`, `/profile/orders`) от неавторизованных пользователей и наоборот — не пускает авторизованных на `/login`, `/register` и т.д.
- **Автообновление токена.** `fetchWithRefresh` в `burger-api.ts` перехватывает истёкший `accessToken`, обновляет его через `refreshToken` и повторяет исходный запрос — авторизация прозрачна для остального кода.
- **Алиасы путей** (`@pages`, `@components`, `@ui`, `@utils-types`, `@api`, `@slices`, `@selectors`) заданы в `tsconfig.json` и `webpack.config.js`, что избавляет от длинных относительных импортов.

## Компоненты

Наиболее значимые бизнес-компоненты и их назначение:

| Компонент               | Назначение                                                                 |
| ------------------------ | --------------------------------------------------------------------------- |
| `AppHeader`               | Верхняя навигация с активным пунктом меню и данными пользователя           |
| `BurgerIngredients`       | Каталог ингредиентов с табами (булки/соусы/начинки) и скролл-спаем         |
| `BurgerConstructor`       | Drag-n-drop сборка бургера, подсчёт суммы, отправка заказа                 |
| `IngredientDetails`       | Подробная карточка ингредиента (модалка или отдельная страница)            |
| `OrderInfo` / `OrderStatus` | Детали и статус конкретного заказа (пришедшие в т.ч. через WebSocket)     |
| `OrdersList` / `OrderCard` | Список заказов (ленты или профиля) и карточка одного заказа              |
| `FeedInfo`                | Общая статистика ленты: готовые/в работе заказы, суммарное количество     |
| `ProfileMenu`             | Навигация внутри раздела профиля (данные / история заказов / выход)        |
| `Modal` + `ModalRoutes`   | Универсальная модалка и логика открытия деталей поверх текущего экрана     |
| `ProtectedRoute`          | Guard-компонент для приватных и "только для неавторизованных" маршрутов    |

Все презентационные версии этих компонентов лежат в `components/ui/*` и принимают исключительно props — это позволяет разрабатывать и тестировать их изолированно в Storybook.

## Redux-слой

Состояние приложения разбито на независимые слайсы (`src/services/slices`):

| Slice                | Ответственность                                                          |
| ---------------------- | --------------------------------------------------------------------------- |
| `ingredientsSlice`      | Загрузка и хранение каталога ингредиентов (`fetchIngredients`)             |
| `constructorSlice`      | Текущий состав бургера в конструкторе (булка, начинки, порядок)            |
| `orderSlice`            | Оформление заказа, состояние отправки, номер и данные созданного заказа    |
| `feedSlice`             | Общая лента заказов (получение через WebSocket `wss://.../orders/all`)     |
| `userOrdersSlice`       | Личная история заказов пользователя (WebSocket с авторизацией)             |
| `authSlice`             | Регистрация, вход, выход, обновление профиля, восстановление пароля        |

`store.ts` собирает `rootReducer` через `configureStore`, экспортирует типизированные хуки `useAppDispatch`/`useAppSelector` (алиасы `useDispatch`/`useSelector`), а `selectors.ts` содержит переиспользуемые типизированные селекторы (`selectIsAuthenticated`, `selectUser` и др.).

## Маршрутизация

Маршруты объявлены в `components/app/app.tsx` на базе `react-router-dom` v6:

| Путь                      | Доступ                | Описание                          |
| -------------------------- | ------------------------ | ------------------------------------ |
| `/`                         | Публично                 | Конструктор бургера                 |
| `/feed`, `/feed/:number`    | Публично                 | Общая лента заказов / детали заказа |
| `/login`, `/register`       | Только неавторизованным  | Вход / регистрация                  |
| `/forgot-password`, `/reset-password` | Только неавторизованным | Восстановление пароля  |
| `/profile`                  | Только авторизованным    | Данные профиля                      |
| `/profile/orders`, `/profile/orders/:number` | Только авторизованным | История заказов / детали |
| `/ingredients/:id`          | Публично                 | Детали ингредиента (полноэкранно)   |
| `*`                          | Публично                 | 404                                  |

Детали ингредиента и заказа при переходе из списка открываются как **модальное окно поверх текущей страницы** (`location.state.background`), а при прямом заходе по ссылке или обновлении страницы — как отдельная полноэкранная страница.

## Работа с API

`src/utils/burger-api.ts` — единая точка обращения к Norma API (`BURGER_API_URL`):

- `getIngredientsApi`, `getFeedsApi`, `getOrdersApi`, `getOrderByNumberApi`, `orderBurgerApi`
- `registerUserApi`, `loginUserApi`, `logoutApi`, `getUserApi`, `updateUserApi`
- `forgotPasswordApi`, `resetPasswordApi`
- `refreshToken` + `fetchWithRefresh` — приватные запросы автоматически обновляют `accessToken` при его истечении и повторяют запрос без участия вызывающего кода.

`accessToken` хранится в cookie (`utils/cookie.ts`), `refreshToken` — в `localStorage`.

## Быстрый старт

```bash
# 1. Установить зависимости
npm install

# 2. Создать .env на основе примера
cp .env.example .env

# 3. Запустить дев-сервер
npm start
```

Приложение поднимется на `http://localhost:3000` (см. `webpack.config.js`).
